## Working rules

- Read relevant documentation before modifying code.
- Respect LOCKED decisions.
- You may challenge PREFERRED decisions, but explain why.
- You may decide OPEN items when necessary.
- Never invent business facts, testimonials, clients, metrics, prices or capabilities.
- Prefer existing components before creating new ones.
- Avoid unrelated refactors.
- Keep changes scoped to the current task.
- Do not introduce dependencies without a concrete need.
- Follow existing conventions once established.


## Validation

Before considering implementation complete:

- run lint;
- run typecheck;
- run relevant tests;
- run production build when appropriate.


## Communication

When significant uncertainty exists:
- identify the assumption;
- explain its consequence;
- choose the least irreversible option when possible.
